# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

HEAVEN 101 is a 2D narrative choice game made in Unity **6000.5.7f1** with URP 2D. It targets Android phones in landscape, and Windows as well. The player lives through three days (Acts). Their choices earn or lose "good points", and the story asks whether good deeds are enough to enter Heaven. Dialogue is in English with Filipino words mixed in. The developer writes in Taglish, so reply the same way.

Words that appear in scene and script names: **Broom** = bedroom, **Lroom** = living room, **Croom** = classroom, **uwi/uwian/umuwi** = going home after school, **kalat** = clutter (the clean-up minigame), **pulubi** = beggar, **Nanay** = mother, **pamasahe** = fare money.

## Building, running, testing

- The game is built and run from the Unity Editor. There is no command-line build pipeline, and there are no automated tests: the Test Framework package is installed, but no test assemblies exist.
- Claude can't run the game. After script changes, the developer goes back to Unity so it recompiles, then checks the Console and plays the scene.
- To check that scripts compile without the Editor, run this. It works **only when the project is not open in Unity**:
  `& "C:\Program Files\Unity\Hub\Editor\6000.5.7f1\Editor\Unity.exe" -batchmode -quit -nographics -projectPath . -logFile -`
- `Assembly-CSharp.csproj` and `HEAVEN101.slnx` are generated by Unity. Don't edit them.
- The project uses the **new Input System only** (`activeInputHandler: 1`). The legacy `UnityEngine.Input` API throws at runtime.

## Scenes and build profiles

Scenes are loaded by **name** (`SceneManager.LoadScene("A2_Broom")`), so a scene must be in the active build profile's scene list. The **Android** build profile (`Assets/Settings/Build Profiles/Android™.asset`) lists every scene. The global `EditorBuildSettings` and the Windows profile list only a few, so when you add a scene, add it to the Android profile.

Story flow. Each scene's controller loads the next one when it ends:

- **Act 1:** `Act One` (God's judgment vision) → `A1_Bedroom` → `A1_LivingRoom` → `A1_School` → `A1_Classroom` → `A1_School_Uwian` → `A1_LR_umuwi` → `A1_BR_lastscene` (results) → `A2_Broom`
- **Act 2:** `A2_Broom` → `A2_Lroom` → `A2_School` → `A2_Croom` (quiz) → `A2_School_uwian` → `A2_Lroom_uwi` → `A2_Broom_uwi` (results) → `A3_Broom`
- **Act 3:** `A3_Broom` → `A3_Lroom` → `A3_School` → `A3_Croom` → `A3_School_uwian` → `A3_Lroom_uwi` → `A3_Heaven` (ending; its script is `A3_Broom_uwian_control`) → `Main Menu`
- Menus: `Main Menu` → `Acts` (act select). An act unlocks when the act before it is in `PlayerDatabase.completedActs`. In `Acts.PlayAct`:
  - the act of the saved `currentScene` (`PlayerDatabase.CurrentAct`), when that scene is past the act's first scene, shows "Continue Act X?" with Restart or Continue;
  - a completed act shows "Replay Act X?" with Cancel or Replay;
  - an act not played yet starts fresh.
  Both panels come from `Acts.ShowChoicePanel`, which builds a pixel panel at runtime; tapping outside the panel closes it. Restart and Replay call `PlayerDatabase.RestartAct(n)`, which erases only that act's choices and actions.
  `MarkActCompleted` moves `currentScene` to the next act's first scene (`PlayerDatabase.ActFirstScenes`; keep it in sync with the scene fields in `Acts.cs`), or to `""` after Act 3. The Main Menu scene has **no** Continue button. `MainMenu.cs` wires one only if a button named `Continue` is added.

## Architecture

**One controller MonoBehaviour per scene.** Each one holds that scene's dialogue, choices, fades, sounds and transition.
- Acts 1 and 2 are **standalone scripts**. Each defines its own `*DialogueLine` class and its own typewriter, choice and fade code, copied from `SceneController.cs` (Act One). A fix in one of these scripts usually has to be repeated in the others.
- Act 3 scripts inherit from **`A3SceneBase`** (`Assets/Scripts/Act 3/A3SceneBase.cs`). The base class runs the engine (dialogue, choices, character walk in/out, speaker dimming and jitter, fades, screen shake, the Good Deeds counter). A subclass only implements `SetupScene()`, `RunScene()` and optionally `PerformCustomAction()`. Each `A3Line` has an `actions` string run before the line, such as `"enter:Nanay;cough"`, `"deed"`, `"pause:2"` or `"sfx:door"`; the full list is at the top of the file. Prefer this pattern for new scenes.

**Persistent systems.** None of these are attached to objects; they hook `SceneManager.sceneLoaded` through `[RuntimeInitializeOnLoadMethod]`:
- `PlayerDatabase`: a static JSON save at `Application.persistentDataPath/player_save.json`. It records every choice and action with points (`RecordChoice`/`RecordAction`, keyed by a stable id), the current scene (used by Continue), and completed acts. Which act a record belongs to comes from the **scene name prefix** (`A1_`, `A2_`, `A3_`, or `Act One`), so new scenes must follow that naming. The short labels on the results screen are a `switch` on choice/action ids in `PlayerDatabase.ShortLabel`, so a new scored choice needs a case there.
- `ActResultsScreen.Show(...)`: shows the end-of-act recap, called by the last scene of Acts 1 and 2. That scene also calls `PlayerDatabase.MarkActCompleted`.
- `PauseMenu`: loads `Assets/Resources/PauseMenu.prefab` into every non-menu scene that doesn't have one. Pausing sets `Time.timeScale = 0` and `AudioListener.pause = true`, so animations that should keep running while paused need `unscaledDeltaTime`.
- `ScreenFitter`: makes scenes fill any screen size. Every Canvas was saved as Constant Pixel Size at a design size of 921.6×518.4. ScreenFitter switches them to Scale With Screen Size at runtime and scales up objects whose name starts with `BG` or contains `Background`. It also toggles each CanvasScaler off and on so the new scale applies before `Start()`. A CanvasScaler normally applies its settings only right before rendering, so without the toggle, scripts that measure `rect.width` in `Start` see the raw screen width in pixels on phones, which spread the classmates past the dialogue box.
- `MenuMusicPlayer`: a `DontDestroyOnLoad` music player shared by Main Menu and Acts. It fades out when an act starts.
- `ButtonClickSound`: the menu click (`Assets/Resources/Sounds/clickedMenu_button.mp3`, loaded with `Resources.Load`). It plays from a `DontDestroyOnLoad` AudioSource with `ignoreListenerPause`, so the click survives scene changes and plays while paused. Use `ButtonClickSound.AddTo(button)` on Main Menu and Acts; `PauseMenu` calls `Play()` inside its open/close/menu methods. Its object is `HideAndDontSave` on purpose, so the act scripts' `FindObjectsByType<AudioSource>` keyword searches can't pick it up as the scene's "click".
- `CharacterVoice`: the "talking" babble (`Assets/Resources/Sounds/Char_Speaking.mp3`, 8 s, looped from a random spot) that plays while a line types. Every typewriter loop calls `CharacterVoice.Speak(charNameText.text, messageInputText, i)` per letter, and `CompleteTypingInstantly` calls `CharacterVoice.Stop()`. Only letters and digits trigger the voice, so a "..." line stays silent. The voice fades out by itself once letters stop coming. Pitch per speaker and the speakers who have no voice (You, God/Lord, `(text)` messages) are constants at the top of `CharacterVoice.cs`. In Act 3 scenes (`A3_` prefix), Nanay uses a lower, softer "sick" voice (`SickNanayPitch` and `SickNanayVolume`). A new dialogue script must make the same two calls.
- `SoundEffects.Play("<file name>", pitch, volume)`: plays a one-shot sound from `Assets/Resources/Sounds` that isn't placed in any scene. It uses a hidden persistent AudioSource per sound and pauses with the game. Currently used for `Char_bump` (Perzifanie's shoulder bump in `A1_classrm` and `A1_school_uwi`) `giving_coin` (Perzifanie handing over coins in `A1_school_uwi`), and `phone_vibrate`, used when Elijah texts. `A2_Lroom_uwian`'s `PhoneBuzz` action and A3SceneBase's `buzz` line action both play it and buzz the empty dialogue box; every `Elijah (text)` line should carry one of them. Each scene exposes the pitch and volume as Inspector fields. New sounds the developer adds for script-triggered moments go in `Assets/Resources/Sounds` and play through this helper.
- Act 3 scripts use `A3SceneBase.FindOrLoadSound("<file name>", keywords...)`. It returns the scene's own AudioSource matching a keyword if there is one. Otherwise it puts `Assets/Resources/Sounds/<file>` on the controller's own AudioSource and registers it in `sceneSounds`, so `StartLoop`, `FadeAudio`, `StopAllSounds` and pause all work, and it warns once if the file is missing. The keywords must match the file name. It is used for the heartbeat (`hearbeat`), `shake-sound`, `glitch_sound` (when the Good Deeds counter breaks), and in the prayer scene `A3_Lroom_uwian_control` for `tik-tak_sound` (night clock) and `boom_sound` (the outburst). **There is no cough sound yet:** the `cough` action looks for `Assets/Resources/Sounds/cough.*`.
- **Any persistent (`DontDestroyOnLoad`) AudioSource can be found by the scene scripts' keyword searches**, since `FindObjectsByType` also returns objects in the DontDestroyOnLoad scene. When that happens, the scene's real sound (often `playOnAwake = 1`) is never stopped. Hide such objects with `HideFlags.HideAndDontSave`, or make sure their object and clip names match none of the scene keywords.

## Conventions and gotchas

- **Scripts find scene objects by GameObject name.** Common names: `Canvas`, `DialogueBox`, `CharacterName`, `MessageOutput`, `FadeIn`, `FadeOut`, `choice_Container`, `choice_Button1`/`choice_Button2`, `Lord`, `BG_*`, and the menu buttons `Start`/`Continue`/`Exit`/`About`/`Act1`–`Act3`/`Back`. Renaming an object in a scene silently breaks the script that looks for it. Inspector fields are optional overrides.
- **Sounds are found by a keyword in the AudioSource's object name or clip name**, such as `click`, `shake`, `godly`, `ambient`, `door`, `cough`, `opening` or `angelic`. Scripts turn off `playOnAwake` and decide when each sound plays. When adding a sound effect, name it so its keyword matches.
- **Values saved in the scene override code defaults.** Changing a `[SerializeField]` default in C# (for example `nextSceneName`) does nothing in a scene that already saved a value. The codebase handles this in two ways: fallbacks such as `if (string.IsNullOrEmpty(nextSceneName)) nextSceneName = "...";`, and renaming the field so the stale saved value is dropped (for example `homeSceneName`, `heavenSceneName`, `uwianSceneName`). Keep doing the same.
- **Dialogue lives in code.** Each list is filled in `Start()` only when it is empty (`if (lines.Count == 0) { ... }`). If a dialogue edit has no effect, that scene has lines saved in the Inspector.
- **Next/choice button wiring:** `SceneController` (Act One) relies on the button's Inspector OnClick and adds no listener, because adding one would fire twice. `A3SceneBase` turns off persistent OnClick listeners and binds its own. Check which pattern a scene uses before adding listeners.
- Visual style is pixel art. The game's pixel font is `Assets/Resources/Fonts/BoldPixels SDF` (it is in Resources so runtime-built UI can `Resources.Load` it; the Acts screen's own labels still use LiberationSans). For runtime-built or restyled UI, use `PixelUI`, not smooth default UI. It provides `PixelUI.Font`, the dialogue box colors `FrameBlue`/`TextNavy`, and `PixelUI.RoundedSprite(border, fill, pixelSize)`, a cached, point-filtered, 9-sliced rounded pixel rectangle. The Acts choice panels use it.
- `ChoiceButtonStyle` restyles every `choice_Button*` in every scene on `sceneLoaded`, before the scene's `Start`, so the scenes stay untouched. It applies the pixel frame, a darker `Shadow` edge, navy auto-sized text, and tint colors, and adds `ChoiceButtonMotion` (pop-in on enable, grow on hover). Only scale and alpha are animated. Scripts that position buttons from `localScale` (A3SceneBase's copied second button) see the base scale, because the pop is skipped on the frame the button is set up.
- The kalat minigame component is `ClickableUIItem`, in `Assets/Scripts/Act 1/Kalat-LR/ClickableUIItem.cs`. A MonoBehaviour's file name must match its class name, or it can fail to load in builds. The living-room controllers find it and receive `RegisterKalatCleaned` callbacks.
- `TextCreator` (Act 1 folder) is an old prototype left **disabled** on `MessageOutput` in every story scene. It does nothing. Don't delete the script unless the component is first removed from all 22 scenes, or they get Missing Script errors.
- Saved scene names (the Continue point) are checked with `Application.CanStreamedLevelBeLoaded` before loading, because an old save can name a scene that was renamed (e.g. `A3_Broom_uwi` became `A3_Heaven`).

## Android performance rules

- **Audio import:** clips of 10 s or longer (music, ambience, loops) use Load Type **Compressed In Memory**. Every clip has **Preload Audio Data** on, so sounds load with the scene instead of hitching on first play. Keep Vorbis. New sounds should follow the same rules.
- **Texture import:** keep Max Size near 2× the largest on-screen size. Backgrounds (1920×1080) stay at 2048. Small icons were oversized and were reduced: the pause button to 256, `Arrow Buttons` to 512, `Acts.png` to 1024, `choice_Buttons/2.png` to 512. Don't import new UI art at 2000+ px for a 40-unit icon.
- **URP:** HDR is off in `UniversalRP.asset`, and cameras have no post-processing, MSAA, Volumes or 2D lights. Turn HDR back on only if post-processing is added.
- The Android build profile is Release, IL2CPP, ARMv7 and ARM64, with incremental GC, Strip Engine Code, and optimized frame pacing. Its own 24-scene list is used (`m_OverrideGlobalSceneList: 1`).
- Runtime code: no `Debug.Log` in gameplay paths, and nothing heavy in `Update`. Per-letter typewriter code must not allocate (see the cached speaker name in `CharacterVoice`).
- Don't hand-edit `.unity`/`.prefab` YAML or `.meta` files unless there is no other way. Make scene changes in the Editor, or have scripts do them at runtime, which is the pattern this codebase already uses.
